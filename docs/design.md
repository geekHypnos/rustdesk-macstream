# RustDesk MacStream 改造方案

日期：2026-11-13  
版本：v0.4（包含可选 Tailscale 接入模块）  
状态：文档审核完成，配置与验证优先；尚未实施或验证。

本版作为首期执行基线，不再因措辞优化反复扩展方案。本次因用户明确要求加入 Tailscale 模块而调整范围。下一步按本文建立公开文档仓库、验证原版连接并开发最小接入模块；仅在实际测试发现问题、环境发生变化或用户明确调整需求时修订范围。文档审核通过不代表功能或测试验收通过。

## 1. 目标与原则

服务于不同局域网中的双 Mac 远程办公。优先使用原版 RustDesk，通过配置和使用引导改善体验；首期仅为 Tailscale 便捷接入开发必要的少量补丁；其他改造仍需实际痛点证明；性能改造以测量为前提，不承诺达到或超过任何商业产品。

首期不修改现有 HA 或主板服务。本项目不擅自修改路由、DNS、代理、Tailscale ACL、防火墙或系统权限，不启用出口节点、子网路由或公网发布。用户主动安装或启用官方 Tailscale 客户端可能引入网络接口、路由或 DNS 变化；操作前应告知，操作后验证现有代理及连接是否受影响，异常时由用户选择恢复原设置。

## 2. 范围

### 保留

- 固定原版 RustDesk 安装包版本和来源；仅在需要源码改动时记录上游 tag、commit 和构建工具链。
- 记录两台实际 Mac 的芯片和系统版本；仅在性能问题排查时核查实际采集、编码和解码路径。
- 建立原版基线并整理配置引导，首期必须交付可关闭、用户可跳过的最小 Tailscale 接入模块。
- 连接诊断及项目报告提交前脱敏检查。第三方原始日志不得直接上传；自动脱敏仅在功能实际实现并验证后才能宣称提供。密钥扫描辅助检查，不能代替人工审核。
- 经测量证明有必要时开发单点性能补丁。

### 暂缓或排除

- 同时重写采集、编码、解码、渲染。
- 自研拥塞控制、FEC、公共中继及全球节点调度。
- 内嵌 Tailscale 网络栈、VPN 服务、OAuth 或云端账号管理。
- 默认要求 H.265、零拷贝、4K 高帧率或虚拟显示器。
- 自动静默切换到公网中继，以及替代 RustDesk 身份验证。

ScreenCaptureKit、VideoToolbox、Metal 仅为候选技术。先核实固定版本已有实现、系统支持和真实瓶颈，不能把已有功能重复开发。

## 3. 可选 Tailscale 接入

采用外置官方客户端，不打包安装、不收集用户登录凭据。首期同时提供手动连接指南和最小接入界面。模块开发为必做，但使用 Tailscale 对用户完全可选，不自动安装、登录或启用 VPN。以下为首期模块范围：

1. 默认保留原版连接方式，用户主动选择“使用 Tailscale”。
2. 检测受支持的本机客户端和 CLI。区分未安装/无法检测、需要登录、已登录但已断开或暂停、已连接、状态未知；无法可靠判断时显示未知，不以已登录推断已连接。不存在时提供官方安装入口，也允许跳过或手填地址。
3. 需要登录或已断开时引导打开官方客户端，由用户自行登录或恢复连接；不自动执行登录、启用 VPN 或重连命令。
4. 只读读取本机状态；用户主动打开设备选择器后展示可见设备。
5. 选中设备只填入地址，不等于授权连接。保留 RustDesk 密码、对端确认等验证。
6. 用户发起连接后，复用 RustDesk 原有连接、认证和错误提示；不新增端口扫描、独立可达性探测或诊断引擎。Tailscale 只提供本机状态及设备在线信息，连接和认证结果以 RustDesk 原有流程为准。
7. 设备在线不代表可远控，也不代表点对点直连。首期不强制开发自动路径诊断；已有可靠结果时可展示，否则显示未知，路径核查保留在手动排障指南中。

### 被控端 Direct IP 前提

使用 Tailscale 地址连接前，由用户在被控端 RustDesk 中手动启用 Direct IP access，核对该版本的认证配置以及 macOS 屏幕录制、辅助功能等所需权限。具体设置入口以固定版本为准，并在操作指南中记录。本项目不自动修改远端设置，也不代管远端认证凭据。

设备选择器仅提供地址，不保证被控端已经运行 RustDesk、允许 Direct IP 访问或完成系统授权。连接失败时复用 RustDesk 原有错误提示，按指南检查 Direct IP 设置、认证、系统权限及网络访问策略，不直接判定为 Tailscale 故障，不增加独立探测或诊断功能。

实施前仅验证两台目标 Mac 实际安装渠道的 CLI 路径、权限和输出差异；其他渠道标记未验证，不承诺支持。进程调用使用固定可执行文件、参数数组、超时、输出限额和错误处理，不拼接 shell 命令。解析仅提取所需字段，不保存原始设备清单。

以下是未来模块的验收要求，不是已实现功能：关闭模块或未安装 Tailscale 时，须保留 RustDesk 原有连接方式；故障时提示原因，由用户明确选择重试、手填地址或其他连接方式，不静默改变网络路径。当前没有开发此模块。

## 4. 分阶段计划与验收

执行顺序：建立公开文档仓库 → P0 原版基线 → P1 使用指南 → P1b 最小 Tailscale 模块。四项均为首期必做；P2 性能优化与 P3 对外分发仍是条件分支。

### P0：版本核查和基线

交付：原版版本清单、两台实际设备的环境记录、脱敏基线报告。测试范围限于当前系统和主要网络环境，其他芯片、系统版本及安装渠道标记未验证。

- 记录芯片架构、macOS、原版软件版本、显示器分辨率/缩放和主要网络条件，使用设备 A/B 替代真实身份。
- 优先测试用户实际使用的主要网络环境，记录真实点对点或中继路径；局域网对照按需补充，不为覆盖全部网络模式额外建设环境。
- 在实际常用分辨率下进行文字编辑、页面滚动和窗口拖动，记录连接成功与否、清晰度、明显卡顿、断线重连及 CPU/内存占用。
- 复用现有工具，不搭建复杂性能平台，不要求首轮测量帧率、码率或端到端延迟。
- 仅在出现具体问题后追加针对性测量和重复对照；未测指标如实标记。网络 RTT 不等于端到端操作延迟。

通过条件：两台目标 Mac 的原版可用性已确认，失败场景有记录；无需先完成源码编译。无第二台设备或缺少权限时标为未验证，不跳过此门槛。

### P1：配置引导与需求决策（必做）

交付：安装与授权指南、被控端 Direct IP access 与认证配置步骤、可选 Tailscale 手动连接说明、断开/暂停状态处理说明、复用原版错误信息的故障排查清单、脱敏报告。让用户实际使用后记录具体痛点及发生频率。

通过条件：公开仓库内容已经审核，两台实际设备主要环境已经验证，用户能够独立完成连接、授权和基本排障。设备或权限缺失时不得宣称验收通过。即使原版性能已满足需求，也继续完成用户指定的 P1b；无需因此启动性能改造。P1 单独通过不代表首期完成。

### P1b：便捷连接最小实现（首期必做）

依据用户明确要求实施。先固定上游 commit 并验证目标 Mac 可构建；使用上游现有界面和连接流程加入小规模适配，不重写客户端。构建不可用时记录阻塞，不用仅有文档替代模块验收。

必须交付：可关闭的本机 Tailscale 适配器、安装及连接状态检测（含需要登录、已登录但断开/暂停、已连接和未知）、官方入口、用户主动打开的设备选择器、在线状态及地址填入、原版连接错误展示和手动回退。设备选择后仍由用户发起 RustDesk 连接并完成认证。

不引入云端 API、内嵌 VPN、复杂诊断平台或额外后台服务。设置默认关闭；首次启用需明确告知会读取本机可见设备信息。只在相关界面活动时按需刷新并限制频率；关闭模块后停止本项目的读取，不擅自退出或停止官方 Tailscale 客户端。当前范围仅支持两台实际 Mac 的安装渠道，其他环境提供手填地址回退。

测试覆盖：未安装、需要登录、已登录但断开/暂停、已连接、状态未知、CLI 不可用、超时、输出不兼容、对端离线、被控端未启用 Direct IP、远端 RustDesk 未运行、网络访问受限、认证失败、正常连接及模块关闭。连接故障复用原版结果并人工验证，不通过新增端口探测来测试。使用虚构测试夹具，不提交真实设备数据。

通过条件：所有失败均可回到手动连接（不承诺网络故障时手动连接一定成功）；不擅自改变既有 VPN/代理配置；用户主动启用 Tailscale 后检查连接影响；不绕过 RustDesk 认证；本项目生成的日志和导出经验证不泄露身份信息，第三方原始日志须另行审核脱敏。设备在线不得显示为已可远控；已登录不得显示为已连接；未知状态不得猜测为在线。断开状态只引导打开官方客户端，不自动重连。

### P2：条件触发的性能优化

只有 P0 证明存在影响使用的瓶颈，且原版设置无法解决、用户确认继续后才启动；不将性能改造列为 P1b 的依赖。逐项记录“证据—候选补丁—原版对照—回退”。优先小修复和参数调整，不预设必须换架构。

编码或采集后端变更前明确最低系统版本、回退路径和硬件支持。每次只变更一个主要变量，先定义收益指标，再实施测试；收益超出测量噪声且画质、稳定性无明显回归才保留。无收益补丁不合入。

### P3：对外分发准备（条件触发）

仅在决定向其他用户分发修改版时启动，不是建立方案、GitHub 仓库或个人验证的前置条件。个人验证仍使用正常系统权限与可信来源，不关闭系统安全机制。

检查许可证与上游差异，完成签名、公证、TCC 权限引导及升级/卸载测试。个人开发测试与面向其他用户分发分开处理；不得用关闭系统安全机制作为正常安装流程。

## 5. 仓库与维护

项目名 RustDesk MacStream，仓库名 rustdesk-macstream；按用户要求建立公开的设计仓库。首次提交明确限定 README.md、SECURITY.md、docs/design.md；检查文件内容、提交差异及已有历史，确认仓库为公开，不把整个现有工作区、个人配置或设备日志上传。后续引入源码时采用可跟踪上游的小补丁策略，保留版本出处和原许可证。首次仅发布独立文档仓库，不导入其他项目历史。

首期成功标准是原版连接验证、使用文档及 P1b 最小模块均完成并通过目标设备测试；不要求改善视频性能。最低文档为 README、设计方案和 SECURITY。实施后再加入真实构建说明、测试、CI 和变更记录，不创建空壳服务或复杂插件框架。

首期 P1b 必须提供功能开关、补丁回滚及上游更新回归检查。配置阶段保留必要的本机配置备份，不将其提交到仓库。

## 6. 风险与决策门槛

- 维护成本：最小化差异；最小接入模块完成后即停止扩展；若原版性能满足需求，不进入 P2。
- macOS 差异：版本和架构范围以 P0 核查结果为准，不预先承诺全兼容。
- 网络限制：Tailscale 可能走中继，不保证更快；实测后选择连接方式。
- 权限与账号：屏幕录制、辅助功能等由用户在系统界面授权。
- 公开分发：许可、签名、公证和隐私审核完成前不标为正式产品。
